# 苦手表現から別の用例で復習する

## 完了範囲と動作

復習タブの予定項目・保存済み項目に「新しい用例で復習」を追加する。登録表現と元教材を引き継ぎ、別の場面・難易度を指定して端末内LLMで生成する。120文字を超える文章全体の登録では、短い練習表現を利用者が選ぶ。切り詰めて意味を変えない。

モデルの取得・端末確認gate、推論lease、キャンセル、アンロードは既存LLM経路を再利用。未確認LLMでは生成ボタンを無効にし、モデル管理へ案内する。録音・英文・プロンプトの外部送信やログを追加しない。

元の文脈は命令と区別したJSON文字列として渡し、指定表現を含む別の状況を要求する。生成後、通常のJSON/schema検証に加え、大文字小文字・句読点・空白を正規化して同じ本文を拒否し、指定表現の語境界を含む出現を確認する。不適合なら既存の1回の修正リトライを使用し、失敗内容は保存しない。この検証だけで意味上の新規性や英語の正確性を保証するものではない。通常教材と同じ編集・問題メモ・非表示を利用できる。

新用例は別UUIDの通常教材で、`sourceWeakPointID`を端末側で付与する。元の復習予定・成績は変えない。生成画面に関連用例を一覧し、そこから原文非表示の通常リスニング画面とスピーキングへ移動する。学習一覧にも保存する。元の復習項目を後に削除しても生成教材自体は残る。

関連UUIDは既存generated_contentのJSONにoptional追加。旧JSONはnilで復元し、追加schema migrationは不要。モデルが返した関連UUIDやpromptVersionは信用せず、アプリの呼び出し元が実際のUUID・`review-example-v1`を設定する。教材編集では関連と生成元を保持する。

保存コールバックをthrowingに変更し、保存失敗を生成成功として表示しない。通常のLLM教材生成にも適用し、ユーザー編集用の既存エラー表示経路は維持する。

## 検証と残る確認

Docker37 tests成功。新しいテストはコピー・指定表現の欠落/部分一致の拒否、修正リトライ、関連UUIDの保存/再起動復元、旧JSON互換、モデル出力の偽関連をアプリ側の帰属で置き換えることを確認する。quality成功、Swift構文parse成功。iOSビルド・Simulator UI・実際のGemmaを使う別用例生成はまだ確認していない。

既存Simulator復習テストを拡張し、登録表現の引き継ぎ・未確認モデルの無効化・元の復習履歴が維持される導線を検証する。実機ではモデル確認済みのGemmaで生成し、別教材として表示・読み上げ・スピーキング・再起動復元を確認する必要がある。
