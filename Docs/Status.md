## Physical iPhone validation

The connected iPhone is an iPhone 16 on iOS 26.4.2. Older crash reports for **0.1.0 (110.1)** and earlier show launch failures because `CLiteRTLM.framework` could not be found; these predate the runpath correction in PR #15. A crash-style resource report for **111.1** records `EXC_RESOURCE` / `PORT_SPACE` after exceeding the per-process limit of 131,072 ports; its triggering stack is in Apple's TextToSpeech framework while creating a run-loop Mach port, which identifies the failure site but does not prove which app object caused the accumulation. On 2026-11-07, USB confirmed **0.1.0 (118.1)** after the user installed the TestFlight update. A USB launch returned PID 1702, but the process had exited within about 12 seconds; the diagnostic ring contained 500 `appLaunch` events, consistent with the previously observed repeated initialization. The user then updated through TestFlight. USB confirmed **0.1.0 (119.1)**, and the learning home appeared on screen. PID 1706 remained alive after a further 20-second observation. The existing diagnostic ring retained old 118.1 records and showed exactly one new `appLaunch` event for 119.1; that event reported process RSS of 109,330,432 bytes and thermal state `fair`. This confirms the startup lifecycle correction on the physical iPhone for this observation window; it does not establish long-duration stability or model inference behavior.

USB reads, app launch and screenshots work. Remote touchscreen input is unavailable on this iOS 26.4.2 device; accessibility inspection does not provide reliable control activation. The latest screenshot shows the learning home without a crash-report prompt, but interactive acceptance checks still require touching the iPhone.

The following specification checks still need physical-device evidence: offline study after model download; Kokoro/Pocket synthesis, rate, cache and interruptions; microphone recording and Parakeet/on-device Apple Speech transcription; transcript comparison and review persistence after restart; Gemma E2B validation, lesson generation and model lifecycle; RE-USE fixed-sample gate and comparison; per-model timing/memory; model error recovery; and thermal/memory behavior. See [TTS.md](TTS.md), [ASR.md](ASR.md), [LLM.md](LLM.md), and [REUSE.md](REUSE.md) for details and safeguards. USB reads, screenshots, and app launch are available, but automated touchscreen input is not supported by this host/device combination; those interactive acceptance checks remain pending.

## Operating and release notes

- Run local tests and quality checks inside Docker with `bash Scripts/test.sh` and `bash Scripts/quality.sh`. Never install the iOS SDK on the Linux host.
- PR CI runs on GitHub macOS for package tests, iOS Simulator build/analyze, unsigned distribution archive checks, and the review gate. Every merge to `main` triggers the protected TestFlight workflow.
- The short version is **0.1.0**. The build number follows `(workflow run number + 100).attempt`. See [TestFlight.md](TestFlight.md).
- Signing secrets remain in the GitHub `ios-testflight` environment. Do not commit learning data, audio, model weights, certificates, provisioning profiles, or private keys.
