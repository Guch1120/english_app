## Current physical-device evidence

201.1 launched on iPhone 16. The post-update device check confirmed a running app process and one fixed-field appLaunch diagnostic event. Previous acceptance work confirmed offline Gemma generation and saved-lesson restoration, offline Kokoro/Pocket synthesis, repeat playback audible to the user, offline Parakeet/Apple Speech result display, and fixed-sample and recorded-speech RE-USE comparisons. On 2026-11-10, a temporary review item created from an existing sample lesson was graded “普通”: the device showed one review, success 1/failure 0, mastery 100%, and a next review two days later. The matching history entry showed the same grade and next date. On 2026-11-11, another temporary review item was answered with Airplane Mode ON and Wi-Fi OFF; after SIGKILL and relaunch with both settings still off, the saved item, review event and next date were present. That test item and event were then deleted. The saved-review count returned to zero, no test review event remained, and pre-existing learning activity history remained. Airplane Mode was turned off and Wi-Fi reconnected. On 190.1, the Gemma search screen listed nine model files and showed size/license/revision metadata; no model download or removal was performed. After the user reconnected USB, WDA returned `ready: true`; a brief Home-to-app foreground return reopened the Learning tab without changing saved learning data. WDA was stopped and temporary screenshots/logs were removed. This does not verify audio playback in background or on the lock screen. Details and limitations are in [Acceptance.md](Acceptance.md).

On 2026-11-11, iPhone 16 / TestFlight 201.1 Settings showed the data deletion action before diagnostic history. Its confirmation alert showed both Cancel and Delete; selecting Cancel closed the alert without executing deletion. No destructive operation was run, and temporary WDA captures were removed.

On 2026-11-11, the 201.1 offline readiness screen showed TTS, ASR, LLM and RE-USE as prepared/available and displayed the manual airplane-mode checklist. This verified the readiness UI only; this visit did not change connectivity or execute inference.

These observations are individual checks. They do not establish broad model accuracy, semantic lesson quality, long-duration stability or full physical-device acceptance. The RE-USE audible-quality comparison remains intentionally unevaluated at the user's request.

## Remaining acceptance work

See the complete section-by-section source and device audit in [Specification-Audit.md](Specification-Audit.md) and the 18 initial-release conditions in [Acceptance.md](Acceptance.md). Notable open items include additional Parakeet recordings and transcript-level accuracy, RE-USE WER difference, accessibility, microphone-denial retry, audio interruption/lock-screen/background playback, cancellation and error recovery, model download/removal lifecycle, offline upgrade restoration, low-storage behavior, and repeated thermal/memory measurements. A brief app foreground return after Home was observed, but it did not exercise playback. Bluetooth playback routing is untested and deferred at the user's direction; investigate if ordinary use exposes a problem. Any other test that needs user speech or a permission change must be requested clearly; do not delete or replace user recordings.
