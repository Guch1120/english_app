## Current physical-device evidence

208.1 launched on iPhone 16. Docker USB verification confirmed the installed build, a running app process, and one fixed-field appLaunch event; observed RSS peak was 110,018,560 bytes and thermal state nominal. A 2.59 GB Gemma candidate was downloaded, checksum-verified, passed fixed-prompt inference, and then removed by itself; the pre-existing GPU model was preserved and reselected. Previous acceptance work confirmed offline Gemma generation and saved-lesson restoration, offline Kokoro/Pocket synthesis, repeat playback audible to the user, offline Parakeet/Apple Speech result display, and fixed-sample and recorded-speech RE-USE comparisons. On 2026-11-10, a temporary review item created from an existing sample lesson was graded “普通”: the device showed one review, success 1/failure 0, mastery 100%, and a next review two days later. The matching history entry showed the same grade and next date. On 2026-11-11, another temporary review item was answered with Airplane Mode ON and Wi-Fi OFF; after SIGKILL and relaunch with both settings still off, the saved item, review event and next date were present. That test item and event were then deleted. The saved-review count returned to zero, no test review event remained, and pre-existing learning activity history remained. Airplane Mode was turned off and Wi-Fi reconnected. On 190.1, the Gemma search screen listed nine model files and showed size/license/revision metadata. After the user reconnected USB, WDA returned `ready: true`; a brief Home-to-app foreground return reopened the Learning tab without changing saved learning data. WDA was stopped after that earlier visit; for the current authorized model check, the WDA runner was kept running to avoid requiring the user to reenter its restart password while away. This does not verify audio playback in background or on the lock screen. Details and limitations are in [Acceptance.md](Acceptance.md).

On 2026-11-11, iPhone 16 / TestFlight 201.1 Settings showed the data deletion action before diagnostic history. Its confirmation alert showed both Cancel and Delete; selecting Cancel closed the alert without executing deletion. No destructive operation was run, and temporary WDA captures were removed.

On 2026-11-11, the 201.1 offline readiness screen showed TTS, ASR, LLM and RE-USE as prepared/available and displayed the manual airplane-mode checklist. This verified the readiness UI only; this visit did not change connectivity or execute inference.

These observations are individual checks. They do not establish broad model accuracy, semantic lesson quality, long-duration stability or full physical-device acceptance. The RE-USE audible-quality comparison remains intentionally unevaluated at the user's request.
