## Physical iPhone validation

The connected iPhone is an iPhone 16 on iOS 26.4.2. Older crash reports at 07:08 and earlier show **0.1.0 (110.1)** and older builds failing at launch because `CLiteRTLM.framework` could not be found; these predate the runpath correction. USB metadata confirms **0.1.0 (114.1)** installed. A crash-style resource report captured at 08:44 is for **111.1**, whose process had been running since 07:29; it records `EXC_RESOURCE` / `PORT_SPACE` after exceeding the per-process limit of 131,072 ports. This is a long-running-process resource exhaustion, not an immediate launch failure. At 09:16 CoreDevice launched 114.1 as PID 1627, and the learning home was visible behind an iOS crash-report sharing prompt. After flushing and pulling reports, no crash report for 114.1 was found. The prompt still used the legacy display name “English learning App”; the available 111.1 resource report does not establish that it caused this prompt. After the user reported a launch-immediate crash, 114.1 was restarted through CoreDevice at 09:19 as PID 1640; the home and lesson list rendered, and the process remained alive. Thus the reported failure has not been reproduced on the installed 114.1 build. TestFlight uploads **115.1** and **116.1** succeeded; Apple processing/availability and installation of newer builds on the iPhone are not confirmed. The merge-triggered **117.1** build was in progress at this status update.

USB reads, app launch and screenshots work. Remote touchscreen input is unavailable: CoreDevice rejects taps because remote control requires iOS 27 or later. The remaining interactive checks still require dismissing the crash-report prompt and using the app on the iPhone.

The following specification checks still need physical-device evidence: offline study after model download; Kokoro/Pocket synthesis, rate, cache and interruptions; microphone recording and Parakeet/on-device Apple Speech transcription; transcript comparison and review persistence after restart; Gemma E2B validation, lesson generation and model lifecycle; RE-USE fixed-sample gate and comparison; per-model timing/memory; model error recovery; and thermal/memory behavior. See [TTS.md](TTS.md), [ASR.md](ASR.md), [LLM.md](LLM.md), and [REUSE.md](REUSE.md) for details and safeguards.

## Operating and release notes

- Run local tests and quality checks inside Docker with `bash Scripts/test.sh` and `bash Scripts/quality.sh`. Never install the iOS SDK on the Linux host.
- PR CI runs on GitHub macOS for package tests, iOS Simulator build/analyze, unsigned distribution archive checks, and the review gate. Every merge to `main` triggers the protected TestFlight workflow.
- The short version is **0.1.0**. The build number follows `(workflow run number + 100).attempt`. See [TestFlight.md](TestFlight.md).
- Signing secrets remain in the GitHub `ios-testflight` environment. Do not commit learning data, audio, model weights, certificates, provisioning profiles, or private keys.
