## ユーザーの方針

- アプリは一般公開せず個人利用に留める。**GUI改修は英語学習に関わる画面（リスニング・スピーキング・復習・教材）を中心にする。** 診断・設定など周辺画面の見た目だけの修正に PR／CI を使わない。
- 流れは「`codex/` ブランチ → PR → Validate（GitHub Actions）→ マージ → TestFlight → 実機確認」。**Validate の4チェックが通れば、ユーザーの確認を待たずにマージしてよい。**
- ワークフローや既存コードは必要なら自由に変更してよい。
- コンパイル・テストは Docker のみ（`bash Scripts/test.sh`、PR前に `bash Scripts/quality.sh`）。ホストにSDKを入れない。
- **WDA は停止しない。** 止めると再開時に iPhone でパスコード入力が必要になる。

## 実機操作（WDA）のメモ

- iPhone 16 / iOS 26.4.2、USB接続。WDA は Docker コンテナ `english-trainer-wda-session` で動いている（`docker ps` で確認）。セットアップと再起動の手順は [WDA-Automation.md](WDA-Automation.md)。
- コマンドは次の形で実行する：
  `docker exec english-trainer-wda-session pymobiledevice3 developer wda <subcommand> --userspace --timeout 20`
  主な subcommand：`status`、`launch <bundle id>`、`tap <ラベルまたはid>`、`swipe x1 y1 x2 y2 -d 秒`、`list-items`、`screenshot /output/<名前>.png`、`type`、`press`。
- 座標は pt（画面幅393）。スクリーンショットの px を3で割る。
- TestFlight アプリの「アップデート」ボタンはラベル指定の `tap` では反応しない。ボタン位置で長さ0のスワイプをすると押せる（前回は `swipe 309 211 309 211 -d 0.1`）。
- TestFlight に新ビルドが出るまで、アップロード成功から数十分かかることがある。一覧を下に引いて更新する。
- スクリーンショット・要素ツリー・ログには学習内容が含まれうるので Git に入れない。署名関連のファイルも表示・コミットしない。
