# LLM統合

## 配布元と検索

モデルカタログはHugging Face Hubを検索しますが、結果から利用するのは`litert-community`のLiteRT-LMライブラリに登録されたApache-2.0モデルに限ります。検索で取得したリポジトリ情報のrevisionを40桁のコミットSHAに固定し、`.litertlm`ファイルだけを候補として扱います。README、Pythonコード、その他の実行可能ファイルは取得・実行しません。

ダウンロード前にモデルのファイルサイズとSHA-256をカタログAPIから取得し、ダウンロード後に全バイトを検証します。不完全なファイルやハッシュが異なるモデルはロード対象になりません。アプリ領域へ保存し、iCloudバックアップ対象から除外します。削除はモデル管理画面から行えます。

Gemma 4 E2Bの候補はLiteRT Communityの[モデルリポジトリ](https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm)に公開されている`.litertlm`ファイルから選びます。通常のモデルファイルは約2.59 GBです。実際に必要なストレージは一時領域とOSの空き容量にも依存します。

検索時にHugging Faceへ送る情報は検索語とモデル照会だけです。英文、生成プロンプト、録音、学習履歴は端末外へ送信しません。モデルを一度ダウンロードした後の推論はLiteRT-LMを使って端末内で行います。

モデル検索はユーザーが明示して開始します。取得した候補revisionとインストール状態は端末に保持し、再起動後の教材生成でカタログを再取得しません。モデルはインストール時にSHA-256で検証し、再起動時はローカルの固定パスとサイズを確認します。複数GBのモデルを毎回ハッシュし直して起動を遅らせることはありません。

## 生成と保存

通常の教材画面で設問へ回答でき、回答時の設問と選択肢は履歴へ残ります。教材の修正、非表示・再表示、問題メモと生成元情報の保持は [Lesson-Management.md](Lesson-Management.md) を参照してください。モデルが返したIDを保存用のIDとして信頼せず、生成結果にはアプリが新しいIDを割り当てます。

教材生成の入力はテーマ、難易度、教材形式、任意の目標語句です。LLMCoreはモデルに構造化JSONを要求し、パース、必須項目、文字数、難易度、選択肢の重複、正解インデックスを検証します。形式に合わない出力には、前回の応答を命令として扱わないようJSON文字列として明示して添え、スキーマ例と条件を含めて最大2回修正を依頼します。応答は端末内の推論にだけ渡し、ログや診断には記録しません。検証に通らなければ表示・保存しません。

検証済み教材はSQLiteの`generated_content`と`learning_items`へ1トランザクションで保存され、通常の学習一覧からリスニング・スピーキング練習に使えます。学習履歴や復習スケジュールの判断はLLMに委ねません。

構造検証は正解の意味的な正しさや翻訳品質を保証しません。教材の英文、訳、選択肢、説明は学習用の生成結果として確認してください。TOEICの既存問題はプロンプトで複製しないよう指示しています。

## ランタイムと性能情報

LiteRT-LM Swift Packageは`0.19.1`に固定しています。生成時は共有モデルランタイムの排他リースを保持し、推論完了後に会話とエンジンを解放します。現在はGPUバックエンド、最大コンテキスト2048トークン、出力上限512トークンで実行します。

画面にはモデルロード時間、最初の応答までの時間、生成経過時間、出力文字数、LiteRT-LMが報告するデコードtokens/sec、アプリ全体の最大RSSを表示します。教材検証に失敗して保存できない場合も、その試行で取得した生成計測値を保持します。tokens/secは0.19.1の実験ベンチマークAPIを明示的に有効にし、値が返った場合だけ表示します。RSSは他の音声処理やアプリ機能を含むため、モデル単体のメモリ使用量ではありません。実機で値が得られることと実測値はiPhoneでの確認が必要です。

2026-11-10の154.1実機確認では同じGemma候補・条件で教材生成を2回試し、いずれも`ContentError`で保存されなかった。PR #66で修正promptと最大3回試行、失敗時の計測保持を実装し、Docker testsとGitHub macOS CIを通過した。TestFlight 160.1ではオンラインおよび機内モード中のGemma教材生成に成功し、保存一覧への追加とアプリプロセス終了後の再起動後も保存教材が残ることを確認した。再起動後の別の成功生成ではmodel-load 1.5秒、TTFT 0.8秒、generation 4.8秒、43.1 tokens/sec、process RSS 572.3 MBを画面で確認した。別の成功イベントは固定field診断にRSS 567.8 MBを記録した。各値は一回の観測であり、生成文の意味的品質や異なる熱状態での性能は未評価である。

GitHub ActionsのmacOSジョブではSwift Package、iOS Simulatorアプリ、署名なしアーカイブを検証します。これらはiPhone上のGemmaモデル初期化・生成を検証しません。実機でのモデルロード、安定性、処理速度、熱・メモリ挙動は別途確認が必要です。

実機確認前のモデルを教材生成に使わないよう、ダウンロード後に端末上で固定文を生成する動作確認を設けています。成功するとモデルrevisionごとに確認済み状態を端末へ保存し、その後に教材生成ボタンを有効にします。SimulatorビルドやDockerテストだけでは確認済みになりません。

2026-11-11、iPhone 16／iOS 26.4.2／TestFlight 208.1で利用者承認のもと、`gemma-4-E2B-it.litertlm`（Apache-2.0、revision `3d48132a`、2.59 GB）を取得した。画面でSHA-256検証完了を確認し、固定プロンプトによる端末内ロード・推論も成功した。検証後はこの新規候補だけを削除し、既存2.01 GB GPUモデルが保持され、選択も戻ったことを確認した。取得前の空き容量は74.27 GB。固定プロンプトの成功は教材の意味的品質や長時間・熱条件での性能を保証しない。詳しい操作証拠は[Acceptance.md](Acceptance.md)を参照。
