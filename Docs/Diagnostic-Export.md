# Diagnostic export

The on-device diagnostics screen (Settings → 端末内診断) can prepare a JSON report from the bounded local event log. Sharing requires an explicit tap and selection in the system share sheet; preparing the report does not send it. The export contains only fixed subsystem, action, model, outcome and thermal enums and numeric durations and resource measurements. It omits event IDs, timestamps, app/user identifiers, prompts, lesson text, transcripts, recordings and error descriptions. Event order and measurements can still reveal usage patterns, so users should choose recipients carefully.

The report is an in-memory snapshot and is discarded when the diagnostics screen closes or the diagnostic log is cleared. It does not create an export file. Format version 1 allows future changes to be interpreted explicitly. A fresh snapshot is produced when the user taps the preparation button again.

Docker tests verify the schema and omission of identifiers and timestamps, as well as the existing bounded-log behavior. PR [#117](https://github.com/Guch1120/english_app/pull/117) and Validate run [42935927652](https://github.com/Guch1120/english_app/actions/runs/42935927652) add and pass a Simulator UI test that prepares the report and confirms the share action and disclosure appear without opening the share sheet. On iPhone 16 / TestFlight 208.1, WDA verification confirmed the native share sheet opens and can be dismissed. No destination was selected and no report was sent; physical-device sharing remains unverified.
